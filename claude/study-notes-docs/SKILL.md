# 学习笔记

开始工作前读取 [共同规则](references/principles.md)，三版统一的写法、评论边界和备份行为以该文件为准。教学按共同规则的“教学写作”执行：先确定理解缺口与主线，核对冲突材料，再用能走通的案例解释变化，读回检查内容后交付。以下只说明本平台操作。

## 阅读交付

用户需要当前宿主中的可阅读文档和继续提问的入口。先使用当前环境的工具发现机制核实文档能力，不因工具尚未加载就改用另一平台的 Markdown 规则。正文写完后给原文档的可点击入口，并用真实工具请求打开；代码 diff、源稿和本地备份不能代替主阅读文档。图表未能在阅读入口呈现时改用清楚的流程表。笔记正文只放学习内容，制作过程和能力限制只在确实影响本次使用时简短说明。普通交付不逐项汇报没做的 Word、评论或历史备份。

用户是法律本硕、做 AI 产品，技术从零学。他要的是：**右边一份 Claude Docs 笔记**，边读边选中一段问 Claude、直接改、自己高亮；**本地还有一份离线副本**，Claude 用不了也能看。

整个流程分四步：确认 Docs 可用 → 写笔记 → 回评论 → 同步到本地。

---

## 第一步：确认 Docs 可用

Docs 连接器叫 **Claude Docs**，工具名形如 `mcp__<id>__guide / batch / create / update / read / query / export / delete`（可能是 deferred，用 ToolSearch 找）。有这组工具就直接进第二步。

没有，就调用 `mcp__ccd_connectors__session_connectors_status`，按状态处理：

| 状态 | 怎么做 |
|---|---|
| 列表里没有 Claude Docs | 最常见的原因是换过账号或设备后 app 没重启。请用户按 **Cmd+Q** 完全退出 Claude 再打开（只关窗口不算），然后点开这个会话 |
| pending（连接中） | 刚重启时常见。说明仍在连接中，下一轮按真实状态再查，不保证下一条就可用 |
| failed | `mcp__ccd_connectors__reconnect_session_connector` |
| disabled | `mcp__ccd_connectors__set_session_connector_enabled` |
| needs_auth | 只能用户自己去 Connectors 登录，告诉他在哪点 |

重启后还没有：用内置浏览器打开 `https://claude.ai/settings/connectors`，看账号里的 Claude Docs 是否已连接。查到头仍不行，**停下，直说卡在哪、需要用户做什么**。

**用户否决过、不要主动用的替代方案**：
- 发布成 HTML 网页。用户原话："不是一份文档，而是像一个网页"。
- 自制"像文档"的 Artifact 页面。
- 在 app 的文件面板里读 MD。
- 装 Cursor 或 VS Code 扩展。用户原话："我说了要 Claude 侧边！"
- 转给网页版 claude.ai 代做。
- 另开新会话让用户去点。用户原话："直接帮我弄好"。

用户说"装一个""复现一下"，意思是把 Claude Docs 弄回来。

## 第二步：写笔记

**建文档**
1. 先加载 `anthropic-skills:docs` skill，按 Docs 连接器自己的说明做：先建骨架（标题、日期、每章一个 pending 块），把链接给用户，再一章一章填。
2. 一个专题一份文档，不同主题拆开。行业调研这类时效性强的内容另开对话、另建文档。
3. 建好后登记到本地同步清单（见第四步），并同步一次。

**教学写法**
按共同规则的教学流程组织正文与验收，不以旧回答直接改写或按资料覆盖量安排章节。图需要 Docs widget 时先 `guide(["topic.diagram"])`，核对真实工具说明；画完检查文字与关系是否可读，不能显示时用关系表和正文解释。

---

## 第三步：回评论

评论发过来的轮次，开头是 `[Artifact comment sent to Claude]`，Element path 里的 `;thread=<root id>` 就是要回复的线程。

| 用户说的 | 怎么做 |
|---|---|
| 提问："这是啥""展开讲讲""怎么用" | 在评论里讲透，正文不动，用户明确要求写回后才修改 |
| 又说"没懂" | 换个说法，先讲清这是什么场景，再讲原理 |
| 他的理解有误 | 直接指出哪里不对、把哪两件事混在一起了，再给完整链路 |
| 他纠正你，而且他对 | 按他的说法改正文那一处 |
| "写回原文""补进去" | 才改正文，而且要短，细节留在评论里 |
| 要表格、流程图、删某块 | 直接改正文 |

- 回复用 `create` 一条 utterance，parent 设为 `{"object":"utterance","id":"<root id>"}`。改正文用 `update`，带上 `answering: "<root id>"`。不要用 Artifact 的评论工具，那样回复到不了文档。
- 对话里只回一行，例如"已在评论里回复"，不要把答案再说一遍。
- 回复后保持评论打开；仅用户明确要求时才 resolve。删改挂着评论的原文时先核对并尽量保留锚点，不自动解决或删除评论。
- 用户在评论里提出新的写作偏好时，以后的文档都照做。

---

## 第四步：同步到本地

**用户的要求**：笔记和评论"不应该存在云端、依赖 Claude 账号"，本地要有一份，Claude 用不了时也能看。**但不要用定时任务。** 之前建过每小时跑一次的备份任务，用户说"纯纯白费 token"，已经删了。**不要建任何定时、轮询式的备份。**

**什么时候同步**：只有这两种时候。
- 改完正文或回完评论后，同步这一份文档。
- 用户说"同步一下""存到本地"。

**本地放在哪**：所有笔记统一放在 `~/Documents/学习笔记/`，不分项目。每份文档对应三个文件：
- `<名>.docx`：正文、高亮、流程图，评论作为 Word 批注。
- `<名>.md`：正文纯文本。
- `<名>.评论.md`：评论串和高亮清单。

`.sync/` 里是原始数据和旧版本，用户不用管。

**怎么同步**
1. 新文档先登记进 `~/.claude/study-notes/registry.json`：`{"<project id>": {"name": 短名, "title": 标题, "tab": tab id, "url": 链接, "dir": "~/Documents/学习笔记 的绝对路径"}}`。tab id 用 `read` 读 project，在 `files[0].id`。
2. 对这份文档调用三次工具：
   - `export`（format `markdown`）
   - `export`（format `docx`）
   - `query`（object `utterance`，payload `{"under":{"object":"file","id":"<tab id>"},"limit":500,"afterSeq":<上次看到的最大 seq>}`）。带 `afterSeq` 只拉新增的评论，脚本会和本地已存的 `comments.json` 合并，省得每次拉全量（全量有几万 token）。第一次同步一份文档时不带 `afterSeq`。只改了正文、没动评论时，这一步可以省掉。
3. `sync/build.py` 是保留的旧同步实现，会遍历清单和会话记录；本次没有重新验证它能只处理单份笔记。只有确认输入范围限定到本次目标后才运行，不能为运行它擅改真实清单。否则依据当前工具的完整导出结果直接保存目标笔记与评论副本，保留历史；无法完整导出时说明备份不完整，保留旧完整副本。旧脚本的“（无变化）”输出只代表对应文件未重写，不代表其他副本或界面已同步。
