# PaperMind 交付约定

仅在用户选择 PaperMind 时读取并执行。它是正文阅读和选段讨论的入口；Markdown 是写作与导入文件。不要把宿主的源码预览当成 PaperMind 交付。

## 确认支持能力

查看本机 PaperMind 的 `/api/health` 与项目 `docs/AGENT-HANDOFF.md`。本约定对应 PaperMind 0.5.0 起的 Mermaid 关系图支持；旧版 0.4.0 会把图稿显示成代码，须先按用户授权升级、构建并重启该服务，不能假定仓库更新就是运行中的版本更新。项目地址：https://github.com/zaozhiyi/PaperMind 。

命令不存在时，用已安装项目的 `node bin/papermind.mjs` 代替 `papermind`。沿用用户实际服务端口和数据目录，不另开空库冒充原文档，不读取模型授权文件。

命令被执行权限拒绝时，不重复同一命令，也不换 curl/Python 等方式绕过拒绝。仍可用已授权的文件工具完成正文和图稿；保存后明确“文稿已生成，PaperMind 导入尚未完成”，提供具体被阻止的导入步骤。不能把权限拒绝误判为 PaperMind 不支持图，更不能删图交表。

## 写图与正文

系统或流程笔记在正文加入标准 `mermaid` 围栏代码块，使用 `flowchart TD`、`flowchart LR` 或 `graph` 关系图。PaperMind 阅读页会把它画出来，源码收在“编辑图稿”中。节点用短而清楚的中文，箭头标出传递的内容或动作；图过大时拆成整体图和局部图，不能靠缩得看不清完成交付。

总览只保留主线和关键分叉，把队列读取、状态回填、详情查询等局部往返放到对应章节的小图中。中文标签较长的线性流程优先纵向排列，避免把数个长句横排成一条很宽的图。检查适应宽度后的文字大小；“原始大小”可辅助查看细节，但不应靠它补救一张堆满全系统细节的总览。

图稿不使用配置指令、HTML 标签、外部图片、URL 或点击操作。每图最多 20,000 字符、200 条边，每篇最多 20 图。语法受控不改变事实要求：存储、处理、数据对象与返回路径要分清；示例数字只放在它所属的一次操作与阶段，不能把不同次查询的数量混进一张确定链路图。

关系表可以补字段和编号，不替代图。正文继续按共同教学规则讲清原理，不加入安装、导入、测试日志。

## 导入与更新

新建：`papermind notes import 文件.md`。

继续已有笔记：先 `papermind notes get 文档ID` 读取最新正文、讨论和 revision，合并本次修改后用 `papermind notes import 文件.md --id 文档ID --revision 刚读到的版本号`。不拿旧文件覆盖新编辑；冲突后重新读取合并。文件路径默认用于重试去重，移动文件时继续使用原文档 ID。

导入返回 `id`、`revision`、`url` 和 `diagrams`。需要图的笔记检查 `diagrams.count > 0`；`syntax: valid` 只代表图稿校验通过，`display: pending_browser` 明确表示尚待浏览器显示核验。校验失败会拒绝导入，修正图稿后重试，不删除图来规避失败。旧版缺少这个字段时不能宣称支持图。

## 阅读验收与交付

打开返回的 PaperMind 阅读 URL，查看正文里是否真正出现图、文字和箭头能否看清，刷新后是否还在；同时确认图旁段落可选择并用于讨论。报错或显示源码时继续修正，不能改交关系表。浏览器不可控制时可交付已导入的文档链接，但必须明确“图已通过语法检查，页面显示尚未核验”，不能说完整交付已验收。

最终回复给 PaperMind 阅读链接与笔记主线。用户在另一台电脑操作时，链接中的 `127.0.0.1` 指那台电脑自己的服务；不能把本机测试链接当成另一台电脑已更新的证明。

图稿随正文保存在数据库与 `document.json`，导出的 `README.md` 保留 Mermaid 图稿。使用用户已配置的私有知识库同步流程即可恢复；不为交图上传公网素材，也不把学习笔记提交到公开的 skill 或 PaperMind 代码库。持久化与同步能力按产品验证说明表述，不声称本次未执行的远端同步已完成。
