# 系统说明草稿（虚构材料，无真实产品）

这里的“书”指一个书目，即某一 ISBN 对应的书籍版本；每本实体库存书另有 copy_id。这个任务讨论书目与搜索，不讨论实体借阅处理。

馆员上传介绍 PDF，也可手工录入书目。PDF 原件放在 Vault，系统在 BookDB 写文件登记，字段包括 file_id、object_path、status。解析工作进 TaskQ；其中排的是任务消息，消息带 file_id，解析进程据此找到文件路径读取内容。处理慢时上传界面可以先返回已收到，读者不需要等解析结束。

解析进程抽出标题、作者、ISBN、语种等字段。登记的状态用于展示等待、解析中、成功或失败。原件仍在 Vault。ISBN 相同的资料合并到一个书目 book_id 上，不会因为上传第二份 PDF 就再建一个新书目。资料缺 ISBN 时不能仅凭同名断定是同一个版本，需要补查。

BookDB 的 books 保存书目，documents 保存 PDF 的登记并通过 book_id 引用书目。两份资料可以各自有 file_id，却关联同一个 book_id。不同 ISBN 的版本是不同书目。

BookDB 可以按编号及字段查记录。此系统选择另设 QuickFind 用于读者搜索：从 books 读取书目编号与搜索字段，写成供搜索使用的文档。搜索服务按书名、作者、语种、分类匹配；需要详情时读 BookDB。更新通过异步任务进行，任务积压时数据库已经保存、索引尚未更新。QuickFind 的文档不是新建一本书的主记录。

/search 接口支持 q（书名或作者文本）、language、category、page、page_size，返回 items 和 total；item 包含 book_id、title、author、language、category。没有借出时间、归还结果的查询字段。借阅记录属于独立借阅模块，草稿未提供它的查询接口或与搜索的联查方式。

GUI 搜索由读者在页面填条件，搜索服务查询 QuickFind，页面展示一页结果。ReaderAI 接收读者一句话，根据操作说明调用同一 /search 接口，可以调整条件再次查询，再根据 returned items 做挑选并输出书单。限制是多少、分几步挑选，依当时操作说明和实现而定。

ReaderAI 的“查看更多”保留一次生成的查询条件，重新调用 /search，以搜索服务的排序展示结果，不再调用 ReaderAI 做挑选；不会直接取模型刚才没展示的书继续输出。可能与前次返回内容重叠。

馆员后台另有会员、充值、押金、活动促销、捐赠统计和借阅模块。它们不参与 PDF 解析和按书目字段搜索这条路径。
