# 学习笔记

开始工作前读取 [共同规则](references/principles.md)。三版统一的写法、评论边界和备份行为以该文件为准。以下只说明 Cursor。能力、依赖和验证界限见 [兼容性说明](references/compatibility.md)。

`sources/` 里的旧稿是历史资料，不是现行规则。不要沿用旧 Claude 版在删改前自动 resolve 评论的做法，也不要扫描 Claude 会话记录来找导出结果。

脚本和参考文件都在本 `SKILL.md` 同级目录。安装到 `~/.cursor/skills/study-notes-cursor/` 后使用那一份，不要改去调用 Claude 或 Codex 副本。

## 默认载体

新建笔记且用户没有指定载体时，默认用本地 Markdown：编辑器中打开、修改，并用 Markdown 预览阅读。默认路径是 `~/Documents/学习笔记/<短名> Cursor.md`；用户指定了路径就用那个路径。用户指定的是已有外部文档时，不用 Markdown 替代。

这与 Claude Docs、Codex Page 不同。本地 Markdown 没有那种可选中一段、挂上原生评论线程、再在线程里回复的界面，也没有已在本平台验证过的原生文字涂色。加粗、下划线、引用块和本地评论记录都不是文字高亮。已有 Docs 或 Page 不能自动转换过来。选择某个模型不会带来该模型厂商应用里的文档工具。

不要主动改成网页或自制阅读页，也不要为了模仿侧边文档去安装扩展。用户明确改用 Word 或其他载体时，先做下面的能力核验，再只做已核验的那一项；不能把这次选择说成自动保留了评论、高亮、图片和锚点。

## 开始前核验能力

1. 确定这一份笔记：用户给出的路径、当前打开的文件，或当前选区所在文件。这些以本轮实际提供的文件和选区为准。一次只处理这一份。没有选区时，只读用户指定的那一个文件。
2. 只查看本轮已经提供的工具清单，确认有没有文档类 MCP。不要读取 `~/.cursor` 里的认证或 MCP 配置，不要凭记忆补工具名。
3. 清单里没有可用的文档 MCP：只有新建、且用户没有指定载体时，才用本地 Markdown。用户指定的是已有外部文档时，说明当前访问受限，不能擅自改用 Markdown，也不能新建替代品。不要调用 Claude Docs、Codex Pages、`open_in_codex` 或 documents 插件。
4. 用户明确要操作某份外部文档，且清单里确有对应工具：先读取该工具当前的 schema，再按 schema 调用。schema 没给出的参数不要补。把排队、写入成功、读回确认和界面显示分开说明。读取或导出不完整就停止，保留上一份完整副本。
5. 预览能否渲染 Mermaid、选区能否挂原生评论、Word 预览是否显示黄色，都没有事先验证过。未在本轮读回或看到之前，不要把它们说成已有功能。

## 写笔记

新建前只按这一主题的文件名，查看用户指定目录或默认的 `~/Documents/学习笔记/` 里有没有 `<短名> Cursor.md`。有就继续编辑。只有 Claude 或 Codex 原件时，另存带 `Cursor` 后缀的副本，不覆盖原件。不要扫描聊天日志、`~/.claude`、`~/.codex` 或任何凭据。找不到 Cursor 副本就新建。不要把 Docs 或 Page 自动转成这份笔记。

写法遵守共同规则，并保持这些习惯：

- 一个主题一份文档。先说明整体目标和主线，再按概念依赖展开。用户的问题是覆盖清单，不照提问顺序写成问答。
- 长文开头放 Markdown 目录，链接指向标题。新术语首次出现时加粗，并跟一句大白话；英文缩写给出全称。
- 举例默认用搜索、电商和信息流推荐。对比就地用表。需要前面的概念时就地讲清，正文里不写“见第几章”。
- 流程默认写成步骤或表。可以另附 Mermaid 代码块作为源稿；当前预览没有确认渲染成功之前，不称它为已经画出的图。
- 长篇分章时，每章结尾一句“本章记住”，文末放术语表。不写空的“我的笔记”栏，不要求用户做测验。
- 区分来源事实、自己的归纳和未核实内容。用户以后提出的写作偏好，后续 Cursor 笔记照做。

## 解释、评论与改正文

没有原生评论接口。解释类问题在聊天里把内容讲完，并说明无法写回 Docs 或 Page 的原线程。不要只回“已在评论里回复”。用户没有明确要求记录时，不要另写评论文件。

| 用户说的 | 怎么做 |
| --- | --- |
| “是什么”“没懂”“展开讲讲”“怎么用” | 读取相关正文；若已有本地评论记录，一并读取。聊天里讲透，先说明场景。默认不改正文 |
| 又说“没懂” | 换个说法，先讲清场景，再讲原理 |
| 理解有误 | 指出哪里不对、把哪两件事混在一起了，再给完整链路 |
| 他纠正你，而且他对 | 只改正文那一处 |
| “写回”“补进去” | 才改正文，而且要短；细节留在回答里 |
| 要表格、图、删掉某块 | 修改对应正文。要恢复旧文还是追加新结论不清楚时，先问，正文先保持不动 |
| 明确要求记入评论、写成评论或留下评论记录 | 才把这一次问答追加到 `<短名> Cursor.评论.md` |

本地评论副本的开头写明：

```markdown
> 这是 Cursor 本地记录，不是 Claude Docs 或 Codex Page 的原生评论线程。不能在那些文档里打开、回复或解决。
```

每条记录保留被引用的原文、状态、发言者和时间。新记录的状态写“打开”。回复之后仍保持打开；只有用户明确要求解决或关闭某一条时，才把该条改成“已解决”或“已关闭”。保留已有回复、无关记录和引用。不要自动 resolve，也不要删掉记录来回避对不齐的引用。

改动被评论引用过的文字前，先核对引用还能不能对上原文。能保留就同时保留文字和引用。对不上时说明影响，并确认处理方式。

选区使用本轮真实选中的文字和文件路径，不改写，也不自行去掉首尾空白。同一句出现多次时，用选区所在段落区分；仍然不能唯一确定就停下来问，不猜。Markdown 里的位置不能当作 Word 的字符偏移。

写了本地评论副本时，聊天里说明写入了哪个文件，并再次注明它不是原生线程。聊天中的解释仍然要完整。

## Word（仅用户明确选择时）

这是在另一份 `.docx` 上添加或取消 `w:highlight`，不是给当前 Markdown 增加涂色按钮，也不会和 Docs 或 Page 自动同步。第一次使用时说明这一点。

脚本与本 skill 放在一起：

- [scripts/set_docx_highlight.py](scripts/set_docx_highlight.py)：写入或清除文字高亮。依赖 `lxml`。运行前确认当前解释器可以导入它。缺失时先查现有可用运行环境；在已授权的文件处理任务范围内，可以准备隔离的本地依赖环境，不改全局配置。不要改用其他库临时重写脚本。
- [scripts/extract_highlights.py](scripts/extract_highlights.py)：只读提取高亮范围。只用 Python 标准库。

```bash
python3 scripts/set_docx_highlight.py \
  --docx 来源.docx \
  --out 新版本.docx \
  --text-file 选区原文.txt \
  --action add \
  --source-sha256 当前来源哈希
```

`--action` 用 `add` 或 `remove`。同一原文出现在多个段落时，加上 `--paragraph`，段落号与脚本报出的编号一致。选区原文文件保持原样，不要自行 strip 或改写。

脚本只在匹配恰好一处时写入，并且不覆盖来源、不覆盖已存在的输出。正文若发生变化会取消写入。选区切在图片、域或换行上时会拒绝，不要绕开。跨段选区按段拆开，每段单独调用。

首次写入独立的 `<短名> Cursor高亮.docx`。以后替换 Cursor 工作副本前，若内容有变化，先把上一版放进该笔记目录的 `.sync/history/cursor/<时间戳>/`。原始 Claude 或 Codex 的 `.docx` 不覆盖。工作副本不存在时，说明原始 Word 只是旧快照，不能称它为当前笔记的实时导出。

写入后用提取脚本读回，核对选区原文、颜色、数量和段落文字是否未变。这里只验证文件包里的高亮标记。不要声称 Cursor 界面已经显示黄色，也不要调用并不存在的 documents 插件做渲染验证。

`--page-json` 不是 Cursor 的功能。只有用户另外给出了完整 Page JSON 文件时才传入；匹配结果不是原生高亮锚点。局部 Page 读取会被脚本拒绝。

## 本地备份

只在这一份笔记的正文或本地评论记录改完，或用户说“同步一下”“存到本地”时备份。不建定时任务，不轮询，不扫描聊天日志，不批量处理一个目录。

- 默认目录是 `~/Documents/学习笔记/`，用户另指定时照做。跨平台副本使用 `Cursor` 后缀，不覆盖旧原件。
- 覆盖已有 Cursor 工作文件前，内容有变化才把旧文件复制到同目录 `.sync/history/cursor/<时间戳>/`；内容相同则不重写。
- `.md`、`.评论.md`、`.docx` 分开报告。没写的就说没写。刚更新的 Markdown 不能和旧 Word 一起称为同步完成。
- 文件没有读全时保留上一份完整副本，不用截断内容替换它。

## 跟用户沟通

全程中文。能做的直接做。只有必须由用户选择载体、指出哪一处重复选区，或登录外部文档时才询问，一次只给一步。
