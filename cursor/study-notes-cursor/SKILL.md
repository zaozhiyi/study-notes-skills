# 学习笔记 · Cursor

版本：1.2.0。先读 [共同规则](references/principles.md)，尤其是“教学写作”部分。目标是让用户读懂并继续学习，不能以生成文件代替可用交付。只有当前宿主是 Cursor 时使用本版；模型名称不能决定平台。

## 确定文档与能力

- 从当前对话提炼主题、已有知识和没理解的关系。读已有相关内容，按概念依赖重组；不要把会话流水或内部执行记录写成教材。
- 用户指定已有笔记时继续那一份，不擅自改载体。原生文档需要通过当前环境的工具发现机制核实可用能力；只有找到真实工具与 schema 后才调用。
- 新建且未指定载体时，优先使用确实可用、符合用户选择的文档工具；没有这类工具则采用 Cursor 可访问的本地 Markdown 和阅读预览。不要假设带有 Claude Docs、Codex Pages 或其他应用的插件。
- 外部文档访问确实受限时说明具体缺口；先在聊天回答当前可回答的问题，不擅自新建替代文档，也不把缺口列成通用功能报告。

## 主文档位置与阅读入口

- 已指定路径就沿用。未指定时，新建文件笔记优先使用当前工作区中合适的笔记目录，例如 `notes/<主题>.md`；确认目录不是技能库本身或禁止放文档的代码目录。没有合适工作区时使用用户可打开的文档目录并提供入口。
- `~/Documents/学习笔记/` 用作默认独立备份位置，不要求把主文件写到工作区外。备份名用 `<短名> Cursor.md`，保留跨平台原件。
- 已有笔记在工作区外时，不直接断言 Cursor 无法打开。先用实际可用的打开文件工具或已确认的桌面 CLI；工具权限确实限制范围时才说明所需的一步操作。不能绕过权限，也不能擅自改原件路径。
- 主文档写完后用真实工具打开文件并请求 Markdown 阅读预览；文件编辑视图和代码 diff 不是渲染后的阅读视图。无法操作界面时，返回可点击文件入口和已核实的一步预览操作（本机 macOS Cursor 为 `Shift+Cmd+V`，其他系统以真实命令为准），准确说明尚未实际打开预览。
- 不安装新的阅读扩展，不造网页阅读器来替代用户选定文档。若用户另行选择载体，则按其要求处理。

## 编写与检查

按共同规则中的“教学写作”完成以下内容工作，再操作预览与备份：

1. 从用户的理解缺口确定主线和必要前置知识。先给全貌，再讲关键关系；对话材料中的其他功能和历史数字按关联程度安置。用户说没懂的旧回答必须重新设计解释，不能直接改写成更短的笔记。
2. 核对关键材料和冲突。此前助手的回答不是原始证据；数字、步骤和能力的说法不一致时读取相关原文。找不到证据时准确保留具体未知，不补造事实。
3. 用同一个能够走通的小案例讲原理：读者能看到输入、变化、输出，以及为什么后面要接这一步。例子中的查询限定和参数要对应，各阶段结果与数量不能混用。按需要展示简短记录、编号关系或候选集合，不堆代码和术语。
4. 读回正文，沿案例核对逻辑、来源和覆盖范围；有缺口就修正文稿。再检查目录、表格与阅读入口。普通任务不输出内部规划或审阅清单，只交付笔记和必要使用说明。

需要图时用当前阅读入口确实能显示的图或关系表。无法核验 Mermaid 呈现时采用能说明来源、传递内容和返回位置的关系表，配正文解释；不要把未呈现的图稿交给用户。

## 解释选区、回复和写回

- “是什么/没懂/展开讲讲”默认只解释。若真实文档工具支持原评论线程，就回复该线程并保持打开；只有用户明确要求才解决或关闭。
- 本地 Markdown 通过当前文件和选区上下文在聊天解释。给用户实际可用的提问方式：引用这段文字或把文件/选区加入对话。不要每次重复列举其他平台的评论能力。
- “写回/补进去/纠错/删改/加表或图”才改对应正文；有歧义时保留正文并澄清。选区重复时结合段落和文件版本定位，不猜；首尾空白不自行改写。
- 用户明确要求保存问答记录时才追加 `<短名> Cursor.评论.md`，开头用一行注明是本地记录。保留引用、作者、时间、已有回复和状态，默认打开；不把本地记录冒充原生线程。
- 删改被引用的正文时核对并保留引用关系；无法保留时说明影响并确认处理方式。

## 备份与完成回复

- 仅在相关正文或评论改完、或用户要求同步时，备份本次笔记到默认目录或用户指定位置。内容无变化不重写，有变化先保存历史；不扫描聊天日志，不建定时任务，不自动提交或上传笔记正文。
- Word 只在用户明确选择时处理，读取 [Word 高亮](references/word-highlights.md)。不要为普通笔记附带“没做 Word”等无关说明。
- 最终通常两三句：可点击的阅读入口、笔记讲清了什么，以及确有必要的一步阅读或提问方式。影响使用的阻碍必须说明；无需逐项列举未做的事。
- 交付状态与正文分开。只有文件写入就报告文件已生成；实际确认预览后才能说已打开阅读视图。能力与历史验证范围见 [兼容性说明](references/compatibility.md)，普通笔记任务不用复述这份说明。
