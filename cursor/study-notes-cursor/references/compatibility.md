# 兼容性与验证界限

来源是本仓库已有的两份技能：Claude 版 `claude/study-notes-docs`，以及 Codex 版 `codex/study-notes-pages`。作者是本地 Cursor Agent CLI。模型标识为 grok-4.7-high；初始化日志确认所用模型为 Grok 4.7 256K High。写作日期是 2026-10-08。本文件只说明能力边界和验证范围，不记载凭据或个人联系方式。

三版入口都要求先读 `references/principles.md`。该副本与仓库 `shared/principles.md` 保持相同。写法、默认不改正文、在原评论中回答、评论保持打开，以及只在改完或用户要求时备份，都按这份共同规则执行。`sources/` 中的旧稿是历史资料。旧 Claude 版在删改前自动解决评论等行为，不能当作现行规则。

新建学习笔记且用户没有指定载体时，Cursor 默认使用本地 Markdown，在编辑器中修改，并用 Markdown 预览阅读。这种文件没有 Claude Docs 或 Codex Page 的选区评论线程，也没有已验证的原生文字涂色。加粗、下划线、引用和本地评论记录都不能称为高亮。已经存在的原生笔记不能自动转换。没有原生评论接口时，在聊天中回答，并说明无法写回原线程。只有用户明确要求记录，才写入本地评论副本，并标明它不是原生线程。

文档工具以本轮已经给出的工具清单为准。不读取 `~/.cursor` 的认证或 MCP 配置，也不假设本环境带有 Claude Docs、Codex Pages、`open_in_codex` 或 documents 插件。用户指定一份已有外部文档，而清单里没有对应工具时，说明访问受限；不能擅自改成 Markdown，也不能新建一份替代品。未知的预览、评论或涂色能力，不能在未核验时写成已有功能。选择某个模型，不会带来该模型厂商应用里的文档工具。

两份 Word 脚本从 Codex 版原样复用，放在本技能的 `scripts/` 中，以便单独复制安装。`set_docx_highlight.py` 依赖 `lxml`，只在唯一匹配时添加或取消文字高亮，并拒绝覆盖来源、拒绝过期哈希。`extract_highlights.py` 只用 Python 标准库，只读提取高亮。缺少 `lxml` 时先查找已有运行环境；在用户已授权的文件处理范围内，可以准备隔离的本地依赖环境，不修改全局配置。脚本写出的是文件包里的 `w:highlight`。这不表示 Cursor 预览已经显示黄色，也不表示图片、批注和锚点被自动保留。

验证要分开看。本地 Cursor Agent CLI 完成的是技能文件的生成，以及通过阅读核对入口、共同规则副本和两份脚本是否与 Codex 来源对应。主 Codex 在受控临时目录里，用合成的 Word 样例完成了另一层检查：添加和取消高亮、正文与其他压缩包成员保持不变、原文件不被覆盖、重复选区与过期哈希被拒绝。这些通过结果属于主 Codex 的验证，不是本代理自己运行的测试。三份平台技能在真实文档界面中的操作，以及外部文档 MCP 的连接、读取和写回，本次都没有验证。
