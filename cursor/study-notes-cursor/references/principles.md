# 学习笔记共同规则

规则版本：1.1.0。三版共同遵守这些行为规则；文档载体、工具接口、选区定位和备份脚本按各自平台实现。用户当前明确要求优先。旧版平台说明与本文件冲突时，以本文件为准。

## 目标、平台与交付

- 用户要的是能阅读、能理解、能继续提问的学习笔记。创建文件只是中间步骤；主文档须有真实可打开的阅读入口，所用图表可呈现，正文读起来连贯。
- 根据宿主应用、当前工具和用户指定选择适配版，不能用模型名称判断应用。在 Cursor 中用 Claude/Grok/OpenAI 模型仍使用 Cursor 适配版；在 Codex 中不能仅因模型名而选 Cursor 版。只收到仓库链接时，先读取仓库根 SKILL.md 和匹配的适配版。
- 使用当前平台的工具发现机制检查文档能力；工具尚未加载与平台不支持是两回事。不能因第一批工具列表里没有就断言不存在，也不能凭记忆调用未提供的工具。
- 尊重已有文档和载体。主阅读入口与本地备份是不同职责：原生文档交付原文档入口，文件笔记交付当前应用实际可访问的文件与预览入口。全局备份目录不能替代读者能打开的主文档。
- 完成回复通常只需可点击的文档入口、内容主线，以及确有必要的一项使用说明。普通路径不要只包在代码样式里。没有写 Word、没有评论、首次无历史备份等无需逐项汇报。
- 能力限制只在影响本次使用时简短说明，并给出已实现的阅读/提问方式。不把缺少的所有功能、内部工具名和验证过程列成收尾报告；重要事实的不确定性仍须准确说明。

## 写法与内容

- 全程中文，面向技术初学者。先说整体目标和主线，再按概念依赖讲清问题、原理、落地和验证；简单问题直接回答，不机械套用章节。
- 用户提问是内容覆盖清单，不照提问顺序拼成问答合集。新术语首次出现用大白话解释，英文缩写给出全称。
- 默认用搜索、电商和信息流推荐举例；用少量关键层次、完整短段落解释因果。删重复和无关细节，不删必要解释。
- 一个主题一份文档，先查已有笔记，再决定新建。对比用表，流程在平台实际支持时用图；长篇分章笔记每章一句“本章记住”，文末术语表。不要留空“我的笔记”栏，不要求用户做测验。
- 需要前置知识时就地解释，避免只说“见前文/第几章”。关键概念说明是什么、负责什么、与上下游怎样衔接，再用一个贯穿例子解释。步骤清单只辅助正文，不能承担全部原理说明。
- 直白表达仍须保留原理。类比后说清对应的技术概念与边界；例如不能只把“搜索索引”叫作“搜索目录”，却省略它与原始数据的关系和生成过程。
- 简化不能改变概念范围或因果。区分“某一种实现”与“必然如此”、“一种结构”与“整个概念”；例如倒排索引是一种索引结构，不能把它当作所有搜索索引的别名，也不能把采用独立搜索索引说成数据库完全不能搜索。资料只支持示例架构时，说明适用范围。
- 同一条主线不要在开头、流程表、逐章解释、完整案例和结尾反复全文复述。先讲关系，再在对应章节解释关键原理；重复案例只补新的理解点。“本章记住”只用于真正的章，不要求每个短小节都重复。
- 先从对话提炼学习主题与用户的理解缺口，再按主题重组。除非用户要求项目复盘，不把历次会话、谁在何时说了什么、写作过程或项目验收混进教材主线。
- 区分来源事实、自己的归纳和未核实内容：在相关事实旁注明必要来源或日期，详细出处集中在文末。不要固定在开头堆“来源事实/自己的归纳/未核实”三类工作报告。需要现场核实的业务数值不得当成当前事实。
- 教材正文只放学习内容。不要写“下面是流程源稿”“没有在预览确认画出”“目录原先不存在”“没有做 Word”等制作说明。用户问实现过程时再解释。

## 文档与评论边界

- “是什么/没懂/展开讲讲”是解释请求：读取相关正文与评论，在原评论线程实质回答，默认不改正文。平台没有评论接口时在聊天中回答，并说明无法写回原线程。
- “写回/补进去/纠错/删改/加表格或图”才授权修改对应正文。具体要恢复旧文还是追加新结论不清楚时先澄清，同时保留正文。
- 评论回复后保持打开；只有用户明确要求解决或关闭，才改变线程状态。保留已有回复、无关评论和锚点。
- 改动带评论的文字前核对锚点；优先保留文字与锚点。确实无法保留时说明影响并确认处理方式，不通过自动解决、删除或重建评论来规避。
- 使用当前平台真实可用的工具与 schema；不把别的平台工具名、账号连接、会话记录路径当成已经可用的能力。准确区分工具调用排队、写入成功、读回确认和界面显示。

## 文档载体与格式

- 尊重用户已选择的文档和入口，不自动把原生 Page/Docs 改成网页或其他载体。Cursor 的默认载体与局限由 Cursor 版明确说明；选择某个模型不会带来那个模型厂商应用的文档工具。
- 读者需要流程图时，交付可显示的图或同等清楚的流程表。Mermaid 在当前阅读入口不能呈现时，用流程表和解释完成正文；源代码只有用户要求时才作为附录。不能用“未验证的图稿”完成图表交付。
- 写完检查标题与目录、核心概念解释、段落因果和表格显示，能打开预览时实际打开。无法控制预览时，给真实文件入口和必要的一步打开方式，准确说当前状态，不能宣称看到了屏幕。
- Markdown 加粗把标点放在标记外，例如 `**本章记住**：正文`；长文目录使用能跳到章节的真实链接，并在可用的阅读预览里核对。
- 文件笔记写入用户工作区时不自动提交或推送笔记正文；技能仓库与学习内容分别管理。
- 高亮、下划线、加粗和评论是不同能力。只能宣称实际保存和验证过的格式；下划线代替高亮需要用户接受。
- 根据选区原文、段落上下文和文件版本定位；重复文字或不完整读取不能靠猜测。保留正文、图片和其他格式，源文件不覆盖。

## 本地备份

- 仅在正文或评论改完，或用户明确要求同步时备份相关笔记；不建定时任务、轮询或批量扫描无关数据。
- 默认本地目录 `~/Documents/学习笔记/`，用户另指定时照做。迁入或跨平台副本使用平台后缀，不覆盖旧原件。
- 正文、评论和 Word 分别报告完成状态。读取或导出不完整时保留上一个完整副本，不能把截断数据或旧 Word 称为同步完成。
- 内容有变化时先保留历史副本，无变化不重复写。平台导出能力不同，不承诺不存在的自动同步、格式保留或评论锚定能力。
- skill 仓库只保存规则、脚本和必要说明；不把笔记正文、账号凭据、会话记录或备份目录加入仓库。

## 三版如何保持一致

- 本仓库 `shared/principles.md` 是共同规则的唯一维护源；各 skill 的 `references/principles.md` 是供独立安装使用的相同副本。
- 修改共同规则后运行 `python3 scripts/sync_principles.py --write`，再运行 `python3 scripts/sync_principles.py --check`；同步时也检查平台正文是否还有冲突。
- 平台专属能力只在对应 skill 修改，并更新根 README 的能力与验证说明。三个适配版一起发布；原始说明保存在 `sources/` 作为历史资料，不作为当前操作指令。
