# 学习笔记共同规则

规则版本：1.3.0。三版共同遵守这些行为规则；文档载体、工具接口、选区定位和备份脚本按各自平台实现。用户当前明确要求优先。旧版平台说明与本文件冲突时，以本文件为准。

## 目标、平台与交付

- 用户要的是能阅读、能理解、能继续提问的学习笔记。创建文件只是中间步骤；主文档须有真实可打开的阅读入口，所用图表可呈现，正文读起来连贯。
- 根据宿主应用、当前工具和用户指定选择适配版，不能用模型名称判断应用。在 Cursor 中用 Claude/Grok/OpenAI 模型仍使用 Cursor 适配版；在 Codex 中不能仅因模型名而选 Cursor 版。只收到仓库链接时，先读取仓库根 SKILL.md 和匹配的适配版。
- 使用当前平台的工具发现机制检查文档能力；工具尚未加载与平台不支持是两回事。不能因第一批工具列表里没有就断言不存在，也不能凭记忆调用未提供的工具。
- 尊重已有文档和载体。主阅读入口与本地备份是不同职责：原生文档交付原文档入口，文件笔记交付当前应用实际可访问的文件与预览入口。全局备份目录不能替代读者能打开的主文档。
- 完成回复通常只需可点击的文档入口、内容主线，以及确有必要的一项使用说明。普通路径不要只包在代码样式里。没有写 Word、没有评论、首次无历史备份等无需逐项汇报。
- 能力限制只在影响本次使用时简短说明，并给出已实现的阅读/提问方式。不把缺少的所有功能、内部工具名和验证过程列成收尾报告；重要事实的不确定性仍须准确说明。

## 教学写作：先讲通，再精简

### 先确定读者需要理解的关系

- 全程中文，面向技术初学者。写前从用户的话确定学习目标、已懂的部分、卡住的关系和必要前置知识。用户明确说“没懂”的回答是待改写材料，不能作为成功范文沿用；重新组织解释，不只压缩旧稿或换词。
- 对话与附件是材料，学习目标决定正文范围。先给简短全貌，再沿核心关系深入；保留理解它所必需的分支，其他功能、会议数字、历史待办放附录或留给其他主题。用户要求完整主题时覆盖必要内容，但不把资料齐全当成教学完整。
- 按概念依赖安排讲解，用户的问题作为覆盖清单。需要前置知识就在第一次用到时解释；章节安排和术语不能要求读者凭空补逻辑。不机械套固定章节数。

### 核对材料，再使用事实与例子

- 区分原始记录、文档/代码、此前助手解释和讲解设定。此前助手的总结可用来定位材料，不能因为重复出现或加了日期，就升级为已验证的系统事实。
- 多份材料在步骤、数量、能力或口径上冲突时，查可访问的更直接证据和上下文，识别是否属于不同时间、配置或阶段。不能自行把冲突拼成一个确定结论。证据仍不足时，讲清确定的原理，简短标明具体实现待确认；不要用一句“未查线上”包住未经支持的核心断言。事实边界只在影响理解或结论的地方说明；不影响主线的实现细节可略去或集中放来源，避免反复声明未知打断解释。
- 用户已授权阅读历史会话或附件时，读取相关原文并补齐被截断的关键段落；没有返回结果的调用记录不证明成功。不扫描无关历史。将必要来源就近注明，详细出处集中在文末，不把证据整理报告放进教材开头。
- 例子优先用当前主题和用户已熟悉的场景；没有合适场景时再用搜索、电商、推荐。缺少现成例子时，可在材料确认的能力与字段范围内自造一组输入、参数值和演示结果，明确标为讲解设定，不把它称为唯一真实实现；不必因原文没有给出这个例子就省略关键转换。真实结构、接口字段、权限和线上规则仍须有依据。例子必须能够走通：需求中的限定要对应实际条件或证据；数量注明对象、阶段与统计单位。没有支持的关系或能力不补造；职责不同不能自动推断为独立队列、进程或服务，没有声明共享也不证明它们分离。

### 让读者看到原理怎样发生

- 开头用短段落说清整体目标、主线和各部分关系，再逐步引入概念。新术语第一次出现用大白话解释，关键缩写先给中文含义与必要全称，尤其是例子用来作判断依据的概念；需要前置概念时就地补一句解释，不只让读者“见第几章”。类比之后说明对应的技术概念与边界。专业系统、存储内容、处理动作和统计结果不要混成一个概念。
- 在用户卡住的步骤，说明为什么需要它，并展示输入是什么、进行什么处理、输出变成什么、下一步怎样使用。用同一个小案例追踪实际变化；只是同一个人名贯穿、每节各说一句职责，不足以解释机制。
- 展示变化的方式按主题选：文件变成字段、记录之间通过编号关联、查询条件怎样筛出对象、模型收到什么并据什么挑选；也可以是一个推理、决策或计算怎样得到结论。不要求每个名词都套输入输出表，不用代码替代初学者解释。
- 系统、流程或多个组件关系是学习主线时，正文须有一张在最终阅读入口可见的整体关系图；简单概念或纯文字主题不机械加图。图应表达数据从哪里来、经过什么处理、由谁读取、结果返回哪里，局部步骤再用具体例子。关系表可补充字段与编号，不能替代关系图。图中不同阶段的对象、数量和筛选条件与正文保持一致，不把资料里不同次操作拼成同一条确定路径。
- 少量关键层次、完整短段落解释因果。精简删的是重复和旁枝，必要因果可以展开；同一主线不在开头、流程表、章节和结尾反复全文复述。简单问题直接回答。
- 一个主题一份文档，先查已有相关笔记。长篇给目录、每章一句“本章记住”和文末术语表；短文不机械分章。对比用表，不留空“我的笔记”栏，不要求用户测验。教材正文只放学习内容，工具、备份、写作与验收日志留在正文之外。

### 先检查内容，再检查呈现

- 写完读回，由作者同时核对正文、关系图表、术语表和章末结论，再沿案例检查：是否能解释每个关键转变、为什么下一步接得上；需求限定是否保留；各阶段对象和数量是否一致；核心结论是否得到来源支持，尤其是为串联案例而新增的步骤和系统关系；是否遗漏理解所必需的关系、或被支线打断。发现问题同步修正正文与摘要中的相关说法，避免正文改对而图表或术语表仍留旧结论；不能以标题齐全、术语表或“讲清两件事”的完成声明代替内容审阅。
- 笔记应让读者能够沿例子重新说明机制，区分容易混淆的部分，并知道该原理适用的范围。以这些内容判断是否完成，不以篇幅越短越好，也不向用户出题验证。

## 文档与评论边界

- “是什么/没懂/展开讲讲”是解释请求：读取相关正文与评论，在原评论线程实质回答，默认不改正文。平台没有评论接口时在聊天中回答，并说明无法写回原线程。
- “写回/补进去/纠错/删改/加表格或图”才授权修改对应正文。具体要恢复旧文还是追加新结论不清楚时先澄清，同时保留正文。
- 评论回复后保持打开；只有用户明确要求解决或关闭，才改变线程状态。保留已有回复、无关评论和锚点。
- 改动带评论的文字前核对锚点；优先保留文字与锚点。确实无法保留时说明影响并确认处理方式，不通过自动解决、删除或重建评论来规避。
- 使用当前平台真实可用的工具与 schema；不把别的平台工具名、账号连接、会话记录路径当成已经可用的能力。准确区分工具调用排队、写入成功、读回确认和界面显示。

## 文档载体与格式

用户指定 PaperMind 时，读取同目录的 [PaperMind 交付约定](papermind.md)，以其正文阅读页为最终入口；未指定时保留各平台原有载体选择。

- 尊重用户已选择的文档和入口，不自动把原生 Page/Docs 改成网页或其他载体。Cursor 的默认载体与局限由 Cursor 版明确说明；选择某个模型不会带来那个模型厂商应用的文档工具。
- 需要图时，先选择最终阅读入口支持的原生图或渲染语法；不支持时改用该入口能保存和显示的本地图像，不把私人内容上传公网图床。不能因为“还没核验 Mermaid”就退回纯表格。图稿可作为可渲染文档的保存格式，但读者默认看到的须是图，不能是代码块。确实无法交付可见图时，保留已完成内容，明确图尚未交付及具体阻碍，不把表格或未渲染源码判为完成。
- 写完检查标题与目录、核心概念解释、段落因果，并在最终阅读入口查看关系图的节点、连线和文字；刷新后确认仍能显示。打开源码、代码 diff 或另一个应用的预览不算在此入口验收。语法校验通过与页面已经显示是两个状态。无界面工具时完成能做的导入与读回，提供真实链接，明确显示待核验，不声称完整验收通过。
- Markdown 加粗把标点放在标记外，例如 `**本章记住**：正文`；长文目录使用能跳到章节的真实链接，并在可用的阅读预览里核对。
- 文件笔记写入用户工作区时不自动提交或推送笔记正文；技能仓库与学习内容分别管理。
- 高亮、下划线、加粗和评论是不同能力。只能宣称实际保存和验证过的格式；下划线代替高亮需要用户接受。
- 根据选区原文、段落上下文和文件版本定位；重复文字或不完整读取不能靠猜测。保留正文、图片和其他格式，源文件不覆盖。

## 本地备份

- 仅在正文或评论改完，或用户明确要求同步时备份相关笔记；不建定时任务、轮询或批量扫描无关数据。
- 默认本地目录 `~/Documents/学习笔记/`，用户另指定时照做。迁入或跨平台副本使用平台后缀，不覆盖旧原件。
- 正文、评论和 Word 分别报告完成状态。读取或导出不完整时保留上一个完整副本，不能把截断数据或旧 Word 称为同步完成。
- 内容有变化时先保留历史副本，无变化不重复写。平台导出能力不同，不承诺不存在的自动同步、格式保留或评论锚定能力。
- skill 仓库只保存规则、脚本和必要说明；不把笔记正文、账号凭据、会话记录或备份目录加入仓库。

## 三版如何保持一致

- 本仓库 `shared/principles.md` 是共同规则的唯一维护源；各 skill 的 `references/principles.md` 是供独立安装使用的相同副本。
- 修改共同规则后运行 `python3 scripts/sync_principles.py --write`，再运行 `python3 scripts/sync_principles.py --check`；同步时也检查平台正文是否还有冲突。
- 平台专属能力只在对应 skill 修改，并更新根 README 的能力与验证说明。三个适配版一起发布；原始说明保存在 `sources/` 作为历史资料，不作为当前操作指令。
