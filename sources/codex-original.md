# 学习笔记

用原生 Page 承接右侧可编辑文档；本地留独立副本。用户目前接受功能相近的实现，不要求复制 Claude 界面。不要用自制网页替代原生文档，除非用户明确改选。

## 文档与评论

- 新建或编辑 Page 时使用 `pages:write-page` 和当前工具的真实 schema。新笔记未指定位置时建私人 Page；已有笔记先读取，避免重复创建。用 `open_in_codex` 的 page target 请求在右侧打开。
- 一主题一文档。中文，面向技术初学者：概念按依赖顺序展开；术语首次出现用大白话解释；默认用搜索、电商、推荐举例；对比用表，流程用原生 Mermaid；每章一句“本章记住”，文末术语表。用户的问题作为内容覆盖清单，不照提问顺序拼成问答。
- 不写空的“我的笔记”栏，也不要求用户做测验。就地解释所需概念，避免“见第几章”。保留来源等级，事实、归纳、未核实内容分开。
- 用户问“是什么”“没懂”：读相关正文和评论，用评论工具回复原线程，先说明场景，必要时换个例子；默认不改正文。“写回”“补进去”、纠错、删改或要求表格/图时才修改对应正文。删带评论的段落前先回复并处理线程，保留无关评论锚点。
- 读 `list_page_comments` 的真实 thread ID；回复用 `reply_page_comment`，不要套用 Claude utterance、tab 或 widget 的接口。评论回完在聊天里简短说明即可。
- 黄色文字高亮尚未验证支持；不要把块级 Highlight、加粗或评论冒充文字涂色。用户要求原生笔记且拒绝 HTML 时，不创建网页阅读器或网页示范。原生 Page 的下划线已于 2026-10-03 实际验证支持，可在用户接受时将旧高亮恢复为下划线。

## 原生 Page 下划线

- 默认继续编辑原 Page。原生选区工具栏有“设置下划线”；这是现有编辑功能，不需要替换为 Word 或自制网页。
- 2026-10-03 已先通过真实选区工具栏设置下划线，再用 `read_page` 确认原生格式保存为 `<u>文字</u>`。随后用带 block_id/hash 的 `patch_page` 写入相同格式，原生界面显示为真实下划线。这里的标记是 Page 格式的序列化，不是新建 HTML 文档。
- 原有加粗放在下划线内部，例如 `<u>**术语**（解释）</u>`。不要写成 `**<u>术语</u>**` 后与另一段加粗紧邻；此次核验发现这种组合可能显示字面星号。先在一处验证保存和界面显示，再批量恢复。
- 依据原始高亮原文和完整段落定位。遇到同一句出现多次，结合原段落及上下文选择，不能重复标记或猜位置。只改对应段落，保留 block ID、正文、图片和评论。
- 写入后全量读回，逐处核对下划线范围、文字与评论；界面核验后保存本地备份。`open_in_codex` 返回 queued 只代表请求已排队，不代表屏幕已显示。

## Codex 右侧 Word 高亮

这是文件预览的操作路径，不是给当前 Page 增加按钮。用户要求保留原 Page 时不得擅自替换。Codex 的 Word 预览器支持显示 `w:highlight`；通过文档预览的选区批注提交“涂黄”或“取消高亮”，由 Codex 修改 Word 后再打开，黄色保存在文件中。首次使用明确说明这是选区指令流程，不是一键涂色，也不是 Page 与 Word 自动同步。

- 已有选区先读取所指文件，使用真实选中文字和定位信息，不拿 Page 的 Markdown 偏移当 Word 偏移。若精确文字重复，结合段落确认；无法唯一定位时先定位，不猜。
- 使用 [scripts/set_docx_highlight.py](scripts/set_docx_highlight.py)：`--docx 来源.docx --out 新版本.docx --text-file 选区原文.txt --action add|remove --source-sha256 当前来源哈希`；可用 `--paragraph` 消除跨段重复。选区原文文件不得自行 strip 或改写。跨段选区按段逐次处理；复杂图片/域边界由脚本拒绝，不绕开保护。
- 脚本仅改文字高亮，保留正文和其他 ZIP 内容；原始 Claude Word 不覆盖。首次写入独立的 `<短名> Codex高亮.docx`；以后先保存上一版本到 `.sync/history/`，经文档 Skill 的验证后再原子替换工作文件。既有工作副本缺失时说明原始 Word 是旧快照，不能冒称当前 Page 导出。
- 按 `documents:documents` 验证改后的文件；重新提取高亮并核对选区、数量及正文，重新打开工作文件，明确哪些保存/显示步骤已验证。`open_in_codex` 返回 queued 只代表排队，不能宣称已在屏幕显示。
- Page 仍按既有流程编辑与评论；文件高亮不反写 Page。未获用户明确选择，不把其他笔记批量改为 Word，也不改变默认笔记入口。

## 本地备份

仅在正文或评论改完，以及用户要求同步时执行。不要建定时任务或轮询。

- 默认沿用 `~/Documents/学习笔记/`，但迁入 Page 使用 `<短名> Codex`，不覆盖 Claude 原始文件。用户另指定目录时照做。
- 全量读取 Page 并保存原始 JSON；读完整评论列表，若返回 truncated 就停在“备份不完整”，保留此前完整副本，不把截断结果冒充全量。
- 运行 [scripts/save_snapshot.py](scripts/save_snapshot.py)，将工具 JSON 落为 `.md`、`.评论.md`、原始 Page/comment JSON；变更前留历史副本，无变化不重复写。脚本只处理明确提供的数据，不扫描聊天日志猜导出结果。
- 需要更新 Word 离线副本时用 `documents:documents` 的 bundled runtime 和渲染验证流程生成 `<短名> Codex.docx`；真实保留的图、评论、高亮才可宣称保留。原始 `.docx` 是迁移前快照，不是当前 Page 的实时 Word 导出。
- 同步时说明正文、评论、Word 各自完成状态；不把更新后的 Markdown 与旧 Word 混称为同步完成。

脚本用法：`python3 scripts/save_snapshot.py --page-json PAGE.json --comments-json COMMENTS.json --name 'Harness上下文处理调研 Codex' --directory /绝对路径/学习笔记`
